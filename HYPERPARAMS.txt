================================================================================
REPORT OUTPUTS (what to paste / plot)
================================================================================
After each run you should save the whole output folder. Key files:

cli_split  -> split_summary.json (+ train/val manifests)
              Now includes "cli_args" for reproducibility.

cli_embed  -> *.embed_config.json next to each .npz (segment length, overlap, etc.)

cli_sklearn_train -> val_metrics.json
                     val_classification_report.txt
                     val_predictions.csv       (y_true, y_pred, filename)
                     val_confusion_matrix.csv
                     experiment_config.json

cli_torch_train  -> same four val_* plus experiment_config.json
                    (Torch also sets best_epoch_val_accuracy inside val_metrics.json)

cli_synth_balanced -> synthetic_experiment_config.json (under synthetic manifest folder)

CSV clarity: cli_embed outputs only compressed .npz. If classmates say embeddings "produce no CSV", they mix steps:
  downstream sklearn/torch summarize runs emit val_predictions.csv / metrics_comparison.csv. Failures usually mean broken
  paths, unreadable NPZ, write permission/disk space, or a failed/empty embedding chunk — not a missing exporter in cli_embed.

Aggregate for LaTeX/Word tables:
  python -m birdclef_a2.cli_summarize_runs \
    --rows A_logreg=outputs/A_sklearn_head B_hgb=outputs/A_hgb C_torch=outputs/A_torch \
    --out-csv outputs/metrics_comparison.csv

Suggested headline metrics for the report:
  - macro_f1 (primary, class imbalance)
  - weighted_f1
  - balanced_accuracy
  - accuracy (secondary; explain bias toward majority classes)
  - cohen_kappa (overall agreement; NaN if degenerate)

================================================================================
HYPERPARAMETERS BY METHOD (what you can tune + how)
================================================================================

1) DATA SPLIT  (python -m birdclef_a2.cli_split)
   Tunable:
     --val-fraction        default 0.2  (try 0.15-0.25 if you discuss stability)
     --seed                reproducibility; try 2-3 seeds for variance paragraph
     --group-col           optional anti-leakage grouping (if you define a column)
     --label-col           if CSV differs
   Tuning idea: fix one seed for main table; appendix = seed sweep min/max.

2) BIRDNET EMBEDDINGS  (python -m birdclef_a2.cli_embed)
   Tunable:
     --segment-s           window length (e.g. 2.0 / 3.0 / 5.0 s)
     --overlap-s           more overlap => more segments => smoother mean pooling
     --embed-batch-segments VRAM/CPU time tradeoff
     --birdnet-device      GPU:0 selects protobuf SavedModel backend (CUDA TF); omit = tf-lite path CPU
     --birdnet-force-tf-cpu Ignore GPU / use tf backend CPU (fix "No DNN support for stream" on bad stacks)
     --offset-rows         skip first N manifest rows (combine with chunk-rows or manual multi-run resume)
     --limit-rows          cap total rows AFTER offset for this job (omit = through end); with --chunk-rows this caps the
                             whole chunked span (not each pass)
     --chunk-rows          one command does all passes of <=N manifest rows each, writes temp parts under <out>_parts/,
                             merges into single --out-npz, deletes parts unless --chunk-keep-parts (same merged result as
                             one uninterrupted run; merge step still loads full NPZ RAM once)
       Example — full train manifest @ 5000 rows per slice, TF CPU backend:
         python -m birdclef_a2.cli_embed --manifest train.csv --data-root DATA --birdnet-force-tf-cpu \
           --chunk-rows 5000 --out-npz embeddings/train.npz --audio-relative-to train_audio
       Manual shards + cli_merge_embeddings_npz still supported if you want control over filenames or resume semantics.
   Faster local CPU embedding (PowerShell prelude; tune thread counts):
     $env:BIRDCLEF_TF_NO_THREAD_CAPS = "1"
     $env:TF_NUM_INTRA_OP_THREADS  = "22"
     $env:TF_NUM_INTEROP_THREADS    = "6"
     BirdNET pipeline workers (defaults n_workers=1 for rental safety; raise on home PC):
       $env:BIRDCLEF_EMBED_N_WORKERS = "8"        # or "auto" (~physical cores, like official GUI)
       $env:BIRDCLEF_EMBED_N_PRODUCERS = "2"
       $env:BIRDCLEF_EMBED_PREFETCH_RATIO = "2"
     Or CLI: ``--embed-n-workers 8 --embed-n-producers 2 --embed-prefetch-ratio 2``
     (Also try ``--embed-batch-segments`` 24–32 if RAM allows.)
     STDERR noise: ``cli_embed`` sets ``TF_CPP_MIN_LOG_LEVEL=3`` at import (before TF loads). Restore chatter with
       ``--verbose-tf-logging``. If oneDNN lines still appear, set ``TF_ENABLE_ONEDNN_OPTS=0`` (may affect speed/numerics).
     ``overlap-s`` almost equal to ``segment-s`` ⇒ many hops ⇒ slower CPU; smaller overlap ⇒ faster run, different pooled stats.
     Put DATA on SSD; pause heavy antivirus realtime scan on DATA if decode sticks with idle CPU.
   Troubleshooting (GPU protobuf path):
     "No DNN support for stream" @ FusedBatchNormV3 = TensorFlow lacks working cuDNN for your driver/CUDA.
     Fix NVIDIA stack (driver + CUDA-matched tensorflow, e.g. pip install 'birdnet[and-cuda]') or force CPU flags above.
     pthread_create / "can't start new thread" / worker failures = container thread or PID cgroup too tight; defaults use
       BIRDCLEF_EMBED_N_WORKERS=1 unless you raise it; also TF thread caps unless BIRDCLEF_TF_NO_THREAD_CAPS=1.
     If BirdNET asserts len(physical_devices)==1 when multiple GPUs are visible on host: export CUDA_VISIBLE_DEVICES=0
       (otherwise we set it by default only when unset).
     cli_embed merges all segment windows **per audio file into one BirdNET encode session** by default so tiny cgroups don't
       fork a new multiprocessing pipe per overlap window. Tune ``BIRDCLEF_EMBED_ENCODE_SEGMENT_CHUNK`` (e.g. 256) if OOM.
     Run embedding with the project interpreter only: ``.venv/bin/python -m birdclef_a2.cli_embed ...`` — avoid conda ``(main)``
       pulling ``/venv/main/lib`` stdlib/logging next to `.venv` site-packages (mixed installs confuse debugging).
   Tuning idea: small grid (2 segment_s x 2 overlap) -> report best val macro_f1.

3) SKLEARN ON EMBEDDINGS  (python -m birdclef_a2.cli_sklearn_train)
   Tunable:
     --model               logreg | hgb  (strong baseline compare)
     --logreg-c            inverse reg strength (e.g. 0.25, 1, 4)
     --logreg-max-iter     if convergence warnings
     --hgb-max-depth       4-12 typical
     --hgb-learning-rate   0.01-0.1
     --hgb-max-iter        more trees
     --seed
   Tuning idea: manual coarse grid or RandomizedSearchCV (if you extend code).
   For report: state chosen values + one ablation table (e.g. C vs macro_f1).

4) SCRATCH MEL-CNN  (python -m birdclef_a2.cli_torch_train)
   Tunable (CLI):
     --epochs             10-40
     --batch-size         lower if OOM
     --lr                 1e-4 .. 1e-3 common
     --seed
   Code-level (if you edit torch_scratch.ManifestMelDataset):
     segment_s (default 5s), mel n_mels / hop / sample_rate

5) SYNTHESIS  (python -m birdclef_a2.cli_synth_balanced)
   Tunable:
     --target-per-class / --max-target-cap   how aggressive balancing is
     --audio-seconds       length of each clip (VRAM/time)
     --inference-steps     quality vs speed
     --hf-model-id         checkpoint choice
     --verify-birdnet + verify-* thresholds   quality filter strength
     --dtype               fp16 vs fp32
     --seed
